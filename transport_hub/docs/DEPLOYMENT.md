# التثبيت والنشر

```
pip install -e "transport_hub[api]"         # أو [dev] للتطوير
transport-hub --port 8501                   # الواجهة
transport-hub-api --port 8000               # واجهة REST
```
متغيرات البيئة: `TRANSPORT_HUB_WORKSPACE` (مكان البيانات)، `TRANSPORT_HUB_API_KEYS` (مفاتيح الـ API كـ JSON)، `TRANSPORT_HUB_LOG` (INFO/DEBUG) و`TRANSPORT_HUB_LOG_FILE`.

## الأمان
- **البيانات**: كلها في `workspace/` على الجهاز. للقُصّر: شفّر القرص، قيّد صلاحيات المجلد، ولا ترفع الملفات لخدمات خارجية.
- **الـ API**: بدون ضبط المفاتيح كل المسارات (عدا `/health`) ترفض الطلب. المشاهد يقرأ والمدير يعدّل. شغّله خلف HTTPS (عكس وكيل) ولا تعرّضه مباشرة للإنترنت.
- **الواجهة (Streamlit)** بلا تسجيل دخول. للنشر المشترك ضعها خلف بوابة مصادقة (SSO/عكس وكيل).
- **الرفع**: حد الحجم 1 GB، فحص zip (قنبلة ضغط، مسارات خطرة)، وحد الصفوف في CSV. التقارير تهرّب النصوص (لا حقن HTML).

## النسخ الاحتياطي والاستعادة
انسخ مجلد `workspace/` كاملاً. الاستعادة بإعادته لنفس المكان (أو ضبط `TRANSPORT_HUB_WORKSPACE`).

## الأداء
- الأحجام المختبرة: مدينة تجريبية 256 منطقة و6 آلاف رحلة تاكسي وجدول 690 رحلة (ثوانٍ).
- نموذج الجاذبية مصفوفة n×n: الحد 3000 منطقة. جدولة المركبات الدقيقة حتى 2500 رحلة (فوقها مطابقة عظمى بلا تقليل التكلفة). الوصول بالزمن يعمل على عيّنة من نقاط الانطلاق في الأحجام الكبيرة.

## التطوير
`make dev && make lint && make cov`. الـ CI يشغّل Ruff والاختبارات على كل تعديل في `transport_hub/`.
